# Guía de Arquitectura: Agregar Modelos en una DB Única (Global + Tenant)

Este backend usa **una sola base PostgreSQL/Supabase** con dos capas lógicas:

1. **Global**: datos compartidos por toda la plataforma (`users`, `tenants`, `vehicles`, etc).
2. **Tenant-local**: datos de negocio aislados por tenant (`entries`, `rates` y futuros módulos).

La estrategia es de defensa en profundidad:

- Aislamiento en aplicación (`this.prisma.getTenantClient()`, automatizado vía `AsyncLocalStorage`).
- Autorización en aplicación (`TenantMembershipGuard`, validaciones de membership).
- Aislamiento en base (RLS + policies SQL).

`supabase/migrations` es la fuente de verdad del schema SQL.

---

## Flujo oficial para agregar un modelo

Orden recomendado (siempre igual):

1. **Crear migración SQL**
2. **Reflejar schema en Prisma (`prisma/schema/**`)**
3. **Generar cliente + DTOs**
4. **Wirear módulo/servicio/controlador**
5. **Aplicar seguridad tenant (si corresponde)**
6. **Agregar/actualizar tests**

Comandos base:

```bash
make migration NAME=add_<modelo>
# editar SQL en supabase/migrations/<timestamp>_add_<modelo>.sql

make migration-apply
# Si falla prisma generate por Node 18:
PATH="$HOME/.nvm/versions/node/v20.20.2/bin:$PATH" bun run db:generate

bun run build
bun test
```

## 1) Modelo Global

Un modelo global **no** depende de `tenant_id`. Si el desktop necesita crearlo offline,
su `id` debe ser provisto por el cliente (UUIDv7) — no usar `@default(dbgenerated(...))`.

### Prisma schema

Crear/editar en `prisma/schema/global/`.

Ejemplo actual (`Vehicle`, offline-first):

```prisma
model Vehicle {
  // UUIDv7 is generated by the desktop client to support offline-first writes.
  id        String   @id @db.Uuid

  brand     String
  model     String
  type      String?

  createdAt DateTime @default(now()) @map("created_at")
  updatedAt DateTime @updatedAt @map("updated_at")

  entries   Entry[]

  @@map("vehicles")
}
```

> Si el modelo **no** necesita crearse offline, podés mantener `@default(dbgenerated("gen_random_uuid()"))`.

### Servicio/controlador

- En módulo Nest: importar `PrismaModule`.
- En servicio: acceso directo con `this.prisma.<model>`.
- Si acepta `id` del cliente, usar DTO manual en `src/<modulo>/dto/`.

```ts
@Injectable()
export class VehiclesService {
  constructor(private readonly prisma: PrismaService) {}

  create(data: CreateVehicleDto) {
    // data.id es provisto por el cliente (UUIDv7)
    return this.prisma.vehicle.create({
      data: { id: data.id, brand: data.brand, model: data.model, type: data.type },
    });
  }
}
```

## 2) Modelo Tenant-local

Un modelo tenant-local **debe** quedar aislado entre tenants.

### Prisma schema

Crear/editar en `prisma/schema/tenant/` y relacionar con `Tenant`.

Si el modelo necesita sincronización offline (recomendado para todo modelo operativo),
agregar los campos de sync:

```prisma
model Entry {
  // UUIDv7 provisto por el cliente para soporte offline-first.
  id        String @id @db.Uuid

  plate      String    @db.VarChar(10)
  color      String?   @db.VarChar(50)
  enteredAt  DateTime  @default(now()) @map("entered_at")
  leftAt     DateTime? @map("left_at")
  amountPaid Decimal?  @map("amount_paid") @db.Decimal(10, 2)

  // Campos de sync offline-first (obligatorios en modelos syncables)
  version   Int      @default(1)
  syncSeq   Int      @default(0) @map("sync_seq")
  updatedAt DateTime @updatedAt @map("updated_at") @db.Timestamptz(6)

  vehicleId String  @map("vehicle_id") @db.Uuid
  vehicle   Vehicle @relation(fields: [vehicleId], references: [id])

  tenantId String @map("tenant_id") @db.Uuid
  tenant   Tenant @relation(fields: [tenantId], references: [id])

  @@index([tenantId], map: "entries_tenant_id_idx")
  @@index([tenantId, syncSeq], map: "entries_tenant_sync_seq_idx")
  @@index([tenantId, updatedAt], map: "entries_tenant_updated_at_idx")
  @@map("entries")
}
```

Si agregas una relación a `Tenant`, no olvides la inversa en `prisma/schema/global/tenants.prisma`.

### Migración SQL para sync

```sql
CREATE SEQUENCE <modelo>_sync_seq;

ALTER TABLE <modelo>
  ADD COLUMN sync_seq   INTEGER     NOT NULL DEFAULT nextval('<modelo>_sync_seq'),
  ADD COLUMN version    INTEGER     NOT NULL DEFAULT 1,
  ADD COLUMN updated_at TIMESTAMPTZ NOT NULL DEFAULT now();

CREATE OR REPLACE FUNCTION set_<modelo>_sync_fields()
RETURNS TRIGGER AS $$
BEGIN
  NEW.updated_at := now();
  NEW.sync_seq   := nextval('<modelo>_sync_seq');
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- syncSeq en INSERT ya lo asigna el DEFAULT; trigger solo en UPDATE
CREATE TRIGGER <modelo>_before_update
BEFORE UPDATE ON <modelo>
FOR EACH ROW EXECUTE FUNCTION set_<modelo>_sync_fields();

CREATE INDEX <modelo>_tenant_sync_seq_idx  ON <modelo> (tenant_id, sync_seq);
CREATE INDEX <modelo>_tenant_updated_at_idx ON <modelo> (tenant_id, updated_at);
```

### Endpoint de cambios (pullChanges)

Para cualquier modelo syncable agregar en el controlador:

```ts
@Get('changes')
@ApiOperation({ summary: 'Pull incremental changes for offline sync' })
@ApiOkResponse({ type: <Modelo>ChangesResponseDto })
async pullChanges(@Query() query: <Modelo>ChangesQueryDto) {
  return this.service.pullChanges(query);
}
```

Y en el servicio (patrón idéntico a `rates.service.ts`):

```ts
async pullChanges(query: <Modelo>ChangesQueryDto) {
  const items = await tenantPrisma.<modelo>.findMany({
    where: { syncSeq: { gt: query.afterSeq } },
    orderBy: [{ syncSeq: 'asc' }],
    take: query.limit,
  });
  const maxSeq = items.length > 0 ? items[items.length - 1].syncSeq : query.afterSeq;
  return { items: items.map(toDto), maxSeq };
}
```

### Servicio/controlador

- No usar `this.prisma.<model>` directo para modelos locales.
- Usar `this.prisma.getTenantClient().<model>`.
- El controlador DEBE usar `@UseInterceptors(TenantInterceptor)`.
- El controlador DEBE usar `@UseGuards(TenantMembershipGuard)`.

## 3) Seguridad Tenant (obligatoria para modelos locales)

Checklist mínimo:

1. SQL con columna `tenant_id` + FK.
2. Modelo registrado en `TENANT_MODELS` (`src/database/prisma-tenant.ts`).
3. Controlador con `@UseInterceptors(TenantInterceptor)` y `@UseGuards(TenantMembershipGuard)`.
4. Servicio usando `this.prisma.getTenantClient().<model>` (PROHIBIDO pasar `tenantId` manualmente).
5. RLS + policies SQL en la migración.

### Contexto por request automático

- Usar `TenantContextService` (vía `AsyncLocalStorage`), disponible desde `PrismaModule` exportado.
- El `TenantInterceptor` lo inicializa automáticamente.
- **No pasar `tenantId` como argumento** a través de capas de funciones.

## 4) DTOs: generados vs manuales

**Generados** (`prisma-generator-nestjs-dto` → `src/generated/nestjs-dto/`):
- Para CRUD estándar 1:1 con el modelo de DB.
- Regenerados con `make generate` / `bun run db:generate`.

**Manuales** (`src/<modulo>/dto/*.dto.ts`):
- Cuando el contrato HTTP **no mapea 1:1** al modelo de DB.
- Obligatorio cuando el cliente provee el `id` (offline-first): el generador no incluye `id` en CreateDto cuando el campo tiene `@default(...)` en Prisma, pero al eliminar el default el contrato necesita validación explícita.
- Casos típicos en este repo:
  - `rates/dto/` — id cliente, pullChanges, expectedVersion
  - `entries/dto/` — id cliente, snapshots de tarifa, closeEntry
  - `vehicles/dto/` — id cliente
  - `auth/dto/`, `password-recovery/dto/` — payloads que mezclan entidades o no mapean a ninguna tabla

## 5) Seeds de desarrollo (una base, dos capas lógicas)

### Global seed (SQL)

Archivo: `supabase/seed.sql`

Incluye datos globales (tenants + catálogo global de ejemplo). Es idempotente y corre en `make reset`.

```bash
make seed-global
```

### Auth/membership seed

Script: `scripts/seed-auth.ts`

- Crea usuarios demo en Supabase Auth.
- Sincroniza `public.users` + `user_memberships`.
- Solo local (guardrail por `SUPABASE_URL`).

```bash
make seed-auth
```

### Tenant-local business seed

Script: `scripts/seed-tenant.ts`

- Crea `entries` y `rates` de ejemplo separadas por tenant.
- Reutiliza `vehicles` globales.
- Solo local (guardrail por `SUPABASE_URL`).

```bash
make seed-tenant
```

### Seed completo

```bash
make seed-all
```

## Cheat Sheet rápido

| Tema | Modelo Global | Modelo Tenant-local |
|---|---|---|
| Ubicación Prisma | `prisma/schema/global/` | `prisma/schema/tenant/` |
| `tenant_id` | No | Sí |
| `TENANT_MODELS` | No | Sí |
| UUID del cliente | Sí si se crea offline | Sí si se crea offline |
| Sync offline | No (global) | Sí: `syncSeq + version + updatedAt` + trigger + `pullChanges` endpoint |
| Acceso en servicio | `this.prisma.model` | `this.prisma.getTenantClient().model` |
| Seguridad requerida | `JwtAuthGuard` | `TenantInterceptor` + `TenantMembershipGuard` + RLS |
| DTOs | Generados si 1:1 | Manual si tiene `id` cliente o snapshot fields |
